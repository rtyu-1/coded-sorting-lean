# 内存位置与磁盘空间怎样计算

内存上界要覆盖执行状态中的每个数据字段。本模块先把算法工作区编码成一排字，再把物理缓冲区和控制字加入同一份统计。 下文 $H$ 是决定局部排序区大小的参数，$B$ 是物理块字数，$b$ 是逻辑块字数，$d$ 是保存地址或计数器所用的字数。

## 工作区的具体内容

[NormalizationFrames.lean](Framework/NormalizationFrames.lean) 的 `SourceState` 包含以下内容：

| 字段 | 保存的内容 |
| --- | --- |
| `leaf` | 能容纳 $512H$ 条三字记录的局部排序区及长度信息 |
| `readers`、`writers` | 输入输出流缓冲区、基地址、长度及偏移 |
| `transfer` | $b$ 字传输工作区 |
| `scalars` | 当前阶段及若干控制字 |
| `directories` | 三组文件目录 |
| `shapes` | 三组数组维度和调用参数，每组 $13d$ 个字 |
| `top` | $d$ 字的当前程序位置 |
| `pcs` | 每组固定数量的额外控制字 |

`pack` 通过数组拼接将这些字段放入长度为 `sourceCells` 的字数组；`unpack` 用对应的下标区间读回各字段。`unpack_pack` 证明读回结果等于原状态，所以不同工作状态在该数组中有不同表示。

令同时使用的输入流数、输出流数、目录条目数、额外控制字数分别为 $r,s,k,p$。代码中的

$$\operatorname{metadata}=(4r+3s+6k+42)d+1+3p,$$
$$L=\operatorname{sourceCells}=1536H+(r+s+1)b+\operatorname{metadata}.$$

主排序程序固定取 $r=1,s=k=p=0$，所以 $L=1536H+2b+46d+1$。虽然 `p=0`，程序位置仍存放在已有的 `top` 字段中。

## 完整执行状态

`ResidentIndex` 为下面每一部分分配互不重叠的存储位置；`resident` 指明每个位置存放哪个状态字段：

| 部分 | 字数 |
| --- | ---: |
| 算法工作区 `ram` | $L$ |
| 物理中转块 `buffer` | $B$ |
| 逻辑暂存块 `scratch` | $b$ |
| 当前块计数器、输入块数、输出块数 | $3d$ |
| 内层阶段与外层阶段 | $2$ |
| 完整地址，包括磁盘区选择 | $d+1$ |
| 合计 | $L+B+b+4d+3$ |

[SortingResourceBudget.lean](../Bounds/SortingResourceBudget.lean) 取固定预留系数 $C$，令 $H=\lfloor M/C\rfloor$、$b=\max\{1,\lfloor B/C^2\rfloor\}$，并证明当 $M\ge C^2$、$2B\le M$ 时，上述合计至多为 $M$。这里的基数 `Fintype.card` 就是这几组有限下标的数量之和。

## 固定的机器参数与运行中变化的数据

`Configuration` 保存输入数量、内存大小、块大小、字长等规模参数，以及这些参数满足的数值条件。算法开始前，由它确定工作区大小、固定程序和磁盘地址范围。输入值以及运行中变化的控制变量则保存在上述状态字段中。

递归调用需要保存的父层信息写入工作磁盘；当前层只使用已分配的工作区。程序位置可以增长，但它被编码进固定数量的 $w$ 位字中；程序位置的数值以 $N$ 的固定多项式为上界，因此能够用这些字表示。

## 磁盘范围

内存达到固定阈值时，磁盘分为三个互不重叠的区域，每区的块编号类型都是 `Fin (N^E)`，实际共有 $3N^E$ 个块。因为 $N\ge2$，代码给出 $3N^E\le N^{E+2}$；再用 $B\le N$ 得到总字数至多 $N^{E+3}$。指数 $E$ 只依赖固定构造和字长常数，详见[常数的全部依赖](../Theorem31/Constants.zh-CN.md)。

小内存分支使用自然数地址，但同时要求程序的全部访问位于分配区间内，见[小内存执行与地址范围](../SmallMemory/Definitions.zh-CN.md)。
